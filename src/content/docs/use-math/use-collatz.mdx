`use-collatz` is the RustUse crate for small, dependency-free Collatz utilities over positive `u64` values. It exposes the next-step map, full trajectories, stopping-time helpers, parity summaries, and inclusive range verification with checked odd-step arithmetic.

## Purpose

The crate covers focused Collatz exploration helpers without forcing users through a broader number-theory or symbolic dependency surface.

## Current scope

- `collatz_next`, `collatz_sequence`, `trajectory_len`, and `max_value_in_trajectory`
- `stopping_time`, `total_stopping_time`, and `reaches_one`
- `CollatzParity`, `parity`, and `parity_vector`
- `CollatzRangeSummary` and `verify_range`
- `Option`-based handling for invalid input and arithmetic overflow

## Intended role in the set

`use-collatz` sits alongside `use-math` and `use-combinatorics` inside the current math set. Geometry now lives in the sibling `use-geometry` set.

Use it when Collatz trajectories, parity patterns, or stopping-time summaries are the only math support a project needs. Reach for `use-math` when the facade crate becomes the clearer integration point.

## Surface at a glance

| Helper group       | Meaning                                                                         | Failure model                                                                             |
| ------------------ | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Trajectory helpers | `collatz_next`, `collatz_sequence`, `trajectory_len`, `max_value_in_trajectory` | `None` for `0` or checked odd-step overflow                                               |
| Step-count helpers | `stopping_time`, `total_stopping_time`, `reaches_one`                           | `Option` for the counting helpers, `false` for `reaches_one` on invalid input or overflow |
| Parity helpers     | `CollatzParity`, `parity`, `parity_vector`                                      | `None` for invalid input or overflow                                                      |
| Range verification | `CollatzRangeSummary`, `verify_range`                                           | Counts successful and overflowed trajectories across an inclusive positive range          |

All odd steps use checked `u64` arithmetic for `3n + 1`, so the crate reports overflow instead of wrapping.

## Examples

### Generate a trajectory and inspect stopping time

```rust
use use_collatz::{collatz_sequence, total_stopping_time};

assert_eq!(collatz_sequence(6), Some(vec![6, 3, 10, 5, 16, 8, 4, 2, 1]));
assert_eq!(total_stopping_time(6), Some(8));
```

### Summarize a bounded range

```rust
use use_collatz::verify_range;

let summary = verify_range(1, 10);

assert_eq!(summary.checked, 10);
assert_eq!(summary.reached_one, 10);
assert_eq!(summary.overflowed, 0);
assert_eq!(summary.max_total_stopping_time, Some((9, 19)));
assert_eq!(summary.max_trajectory_value, Some((7, 52)));
```

## Validity and overflow model

The Collatz conjecture remains unproven, and this crate does not claim otherwise. The current API is for bounded computational exploration only.

| Concern           | Behavior                                                                   |
| ----------------- | -------------------------------------------------------------------------- |
| `n == 0`          | The simple helpers return `None`, and `reaches_one(0)` returns `false`     |
| Odd-step overflow | The checked step `3 * n + 1` returns `None` instead of wrapping            |
| Terminal parity   | `parity_vector` excludes the final `1` and returns an empty vector for `1` |
| Inclusive ranges  | `verify_range` treats `start..=end` as inclusive and skips `0`             |
