## Overview

The current `use-math` set currently surfaces three public crate tracks. `use-math` is the facade crate for feature-flagged re-exports and a `prelude` module, `use-combinatorics` provides the discrete-math counting track, and `use-collatz` provides bounded Collatz trajectory exploration helpers. Geometry primitives now live in the sibling `use-geometry` set.

Use this page as the combined entry point for the set overview and the `use-math` facade crate itself.

## Facade role

Use `use-math` when you want a curated entry point instead of depending on focused crates one by one.

- Feature-flagged re-exports from supported crates such as `use-geometry`
- Feature-flagged re-exports from supported crates such as `use-combinatorics` and `use-collatz`
- A `prelude` module for common imports
- Shared convenience helpers that belong at the facade layer
- Set-level documentation that shows how the supported crates compose

## Design direction

The facade should stay thin. It should expose high-value conveniences, keep feature flags explicit, and avoid turning the set into a mandatory all-in-one dependency.

Shared conventions and helper types that support the facade belong here only when they make the public surface clearer. They should not become a separate public crate.

## Composition

Reach for `use-combinatorics` when your work centers on counting, permutations, combinations, or other discrete helpers. Reach for `use-collatz` when your work centers on trajectories, stopping times, parity patterns, or bounded Collatz verification. Reach for `use-math` when you want a curated entry point that can re-export selected functionality behind features. Reach for the sibling `use-geometry` set when you need direct 2D primitives.

The sketch below is illustrative only. Names and signatures are not final.
