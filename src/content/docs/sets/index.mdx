RustUse currently organizes its initial docs around two early sets so the launch surface stays easy to understand and adopt.

RustUse currently organizes its public docs around two active sets so facade crates, focused crates, and generated API routes stay easy to navigate.

## Sets

A set is the top-level RustUse domain. Today that means `use-math` and `use-geometry`.

Sets define the shared problem space, naming conventions, and the boundary between the facade crate and the focused crates inside the set.

## Current public sets

- [use-math](/sets/use-math/) - {getPublicCratesBySet('use-math').length}
  public crate tracks spanning the facade plus focused arithmetic, algebra,
  sequence, linear, numerical, and validated-number crates.
- [use-geometry](/sets/use-geometry/) - {getPublicCratesBySet('use-geometry').length}
  public crate tracks spanning the facade plus foundations, primitives,
  transformations, relations, curves, regions, polytopes, configurations,
  complexes, and decomposition or folding crates.

## Current model in practice

- `use-math` keeps a thin facade over focused numeric crates with live stable API routes.
- `use-geometry` keeps a facade over a broad geometry child-crate taxonomy, with one workspace-scoped exception when a package identity is blocked.
- The set pages, crate catalog, and sidebar entries are generated from shared metadata so counts, routes, and statuses stay aligned.

## Status

The current public docs surface covers the active math and geometry sets.
Additional sets should stay out of public navigation until their crate
inventory and live package identities are intentionally ready.
