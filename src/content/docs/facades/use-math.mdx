## Purpose

This facade keeps a thin layer over focused math crates so callers can choose between one dependency and a narrower direct crate for a specific math domain. The facade exists for integration ergonomics; the focused crates remain the clearest path when a project only needs one math concern.

Geometry now lives in the sibling `use-geometry` facade. `use-vector` remains here as reusable vector math, and `use-geode` remains here as exact Geode-array and recurrence helpers rather than spatial geometry.

## Install

Choose the facade when you want one dependency for the current math surface:

```toml
[dependencies]
use-math = "0.0.7"
```

Choose focused crates directly when you want a smaller dependency and API surface:

```toml
[dependencies]
use-rational = "0.0.6"
use-set = "0.0.6"
use-vector = "0.0.7"
```

The facade can also be narrowed with feature flags:

```toml
[dependencies]
use-math = { version = "0.0.7", default-features = false, features = ["prime", "rational", "set"] }
```

## Choose an entry point

| Need                                                             | Start with                                  | Why                                                                           |
| ---------------------------------------------------------------- | ------------------------------------------- | ----------------------------------------------------------------------------- |
| One dependency for multiple math domains                         | `use-math`                                  | The facade enables selected focused crates behind explicit feature flags.     |
| One focused domain such as rational arithmetic or set operations | The focused crate                           | Direct crates keep compile surface, imports, and docs narrower.               |
| Reusable vector, matrix, or linear-system primitives             | `use-vector`, `use-matrix`, or `use-linear` | These crates own math primitives that geometry and other facades can consume. |
| Spatial geometry objects, relations, or constructions            | `use-geometry`                              | Geometry has its own facade rather than living inside `use-math`.             |

## Family map

| Family                           | Crates                                                                                   |
| -------------------------------- | ---------------------------------------------------------------------------------------- |
| Arithmetic and number primitives | `use-arithmetic`, `use-integer`, `use-number`, `use-rational`, `use-real`, `use-complex` |
| Algebra, logic, and sets         | `use-algebra`, `use-logic`, `use-set`, `use-modular`, `use-prime`                        |
| Sequences and counting           | `use-combinatorics`, `use-catalan`, `use-collatz`, `use-series`, `use-geode`             |
| Linear and reusable primitives   | `use-vector`, `use-matrix`, `use-linear`, `use-eigen`                                    |

| Probability and summaries        | `use-probability`, `use-statistics`, `use-trigonometry`                                  |

## Current boundaries

- The `use-math` facade should stay a reexport and convenience layer, not a monolithic implementation crate.
- Focused crate APIs should remain concrete, explicit, and usable without the facade.
- Geometry primitives, shapes, and relations belong in `use-geometry`.
- `use-vector` remains a math primitive crate even when geometry crates depend on it.
