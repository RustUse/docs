## Purpose

`use-geometry` is the feature-gated facade crate for the RustUse geometry workspace. The facade reexports focused child crates, exposes matching namespace modules, and keeps the shared geometry surface available through one dependency when that integration shape is clearer than depending on child crates individually.

## Overview

The current `use-geometry` set surfaces {getPublicCratesBySet('use-geometry').length} public crate tracks: the `use-geometry` facade plus its focused child crates. The set is intentionally broad inside pure geometry, but the facade remains thin: implementation lives in focused crates with explicit boundaries.

## Placement notes

- The facade crate only reexports child crates and shared namespace modules.
- `use-line` is the published package name for line primitives; its Rust library name stays `use_line`.
- `use-geometric-complex` is the published package name for geometric complex primitives; its Rust library name stays `use_complex`.
- `use-vector` remains in the sibling `use-math` workspace and is used by geometry child crates that need vector primitives.
- `use-geode` remains in `use-math` and is not part of the geometry set.

## Current release alignment

The `use-geometry 0.2.1` facade release aligns the public geometry docs with the
child crates that consume `use-vector 0.0.7` from the sibling `use-math` set.
The focused geometry crates in that compatibility wave are `use-point 0.1.0`,
`use-plane 0.1.0`, `use-orientation 0.1.0`, `use-ray 0.1.0`, and
`use-line 0.2.1`, with `use-geometric-complex 0.0.6` resolving the former
complex package identity collision.

RustUse keeps these crates below `0.3.0` while the APIs remain pre-production
and pre-1.0. The generated Rustdocs and stable `/api/<crate>/` routes are the
canonical docs entry points for this release line.

## Example API sketch

The sketch below is illustrative only. Names and signatures can still evolve
while the geometry set remains pre-1.0.

### Validated construction

```rust
use use_geometry::{Point2, Triangle};

let triangle = Triangle::try_new(
	Point2::try_new(0.0, 0.0).expect("valid vertex"),
	Point2::try_new(4.0, 0.0).expect("valid vertex"),
	Point2::try_new(0.0, 3.0).expect("valid vertex"),
)
.expect("valid triangle");

assert_eq!(triangle.area(), 6.0);
assert_eq!(triangle.perimeter(), 12.0);
```

### Working with trusted coordinates

```rust
use use_geometry::{Point2, Triangle};

let triangle = Triangle::new(
	Point2::new(0.0, 0.0),
	Point2::new(4.0, 0.0),
	Point2::new(0.0, 3.0),
);

assert_eq!(triangle.sides(), [4.0, 5.0, 3.0]);
```

### Checking exact vs tolerance-based degeneracy

```rust
use use_geometry::{Point2, Triangle};

let triangle = Triangle::try_new(
	Point2::try_new(0.0, 0.0).expect("valid vertex"),
	Point2::try_new(4.0, 0.0).expect("valid vertex"),
	Point2::try_new(8.0, 1.0e-13).expect("valid vertex"),
)
.expect("valid triangle");

assert!(!triangle.is_degenerate());
assert_eq!(triangle.is_degenerate_with_tolerance(1.0e-12), Ok(true));
```
